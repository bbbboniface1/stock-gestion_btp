POINT 4 — TAILLE MINIMALE DES BOUTONS TACTILES

Constat : components/ui/button.tsx ligne 32, la taille "sm" utilise
min-h-8 (32px), en dessous du minimum recommandé pour un usage tactile
fiable (44px iOS / 48px Material), particulièrement critique pour un
usage avec des gants de travail.

Étape technique précise (UN SEUL fichier à modifier, source unique de
vérité pour tous les boutons "sm" de l'app) :
- Dans components/ui/button.tsx, change uniquement :
  sm: "min-h-8 rounded-md px-3 text-xs"
  en :
  sm: "min-h-10 rounded-md px-3 text-xs"
  (min-h-10 = 40px, un bon compromis entre lisibilité tactile et
  densité d'affichage sur les tableaux qui utilisent beaucoup de
  boutons "sm" côte à côte)
- NE TOUCHE PAS à "default", "lg", "icon", ni à la largeur (px-3 reste
  identique) — seule la hauteur change.

TEST : après ce changement, vérifie visuellement les zones à forte
densité de boutons "sm" (actions par ligne dans products.tsx, users.tsx,
project-detail.tsx) pour confirmer qu'aucune ligne ne devient trop
haute ou que les boutons ne se chevauchent pas sur mobile étroit (375px).

POINT 5 — FORMATAGE DES NOMBRES/DEVISE CENTRALISÉ

Constat : la fonction de formatage `n.toFixed(2)` est dupliquée à
l'identique dans invoice-detail.tsx (ligne 21), invoices.tsx (ligne 21)
et invoice-new.tsx (ligne 22), sans passer par Intl.NumberFormat, donc
pas de séparateur de milliers et pas de gestion correcte des devises
sans décimales (comme XOF/CFA).

Étapes précises :
a) Crée un nouveau fichier src/lib/formatCurrency.ts (ne touche à rien
   d'existant) avec une fonction unique :
   export function formatCurrency(amount: number, currencyCode: string): string {
     const isZeroDecimal = currencyCode === "XOF" || currencyCode === "XAF";
     return new Intl.NumberFormat("fr-FR", {
       minimumFractionDigits: isZeroDecimal ? 0 : 2,
       maximumFractionDigits: isZeroDecimal ? 0 : 2,
     }).format(amount) + " " + (currencyCode === "EUR" ? "€" : currencyCode === "USD" ? "$" : currencyCode === "XOF" ? "FCFA" : currencyCode);
   }
b) Remplace les 3 fonctions `fmt`/formatages dupliqués dans
   invoice-detail.tsx, invoices.tsx et invoice-new.tsx par un import de
   cette fonction unique : import { formatCurrency } from "@/lib/formatCurrency";
   et appelle-la avec le currencyCode de l'entreprise (déjà disponible
   via useCompany() dans ces pages, vérifie le nom exact du champ dans
   CompanyContext).
c) NE TOUCHE PAS au backend (artifacts/api-server), uniquement au
   frontend pour ce point — le formatage du PDF sera traité séparément.
